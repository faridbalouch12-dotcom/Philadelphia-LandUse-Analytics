## Key concepts covered

**Grain** — The atomic unit a table row represents. Locks both the unit of uniqueness and the type of fact. "One row per [business object or event]."

**Grain shapes what gets filtered:** The `status = 'Issued'` filter in `fct_permits` is part of the grain definition — it defines which events qualify, not just which rows survive.

**Grain shapes what gets deduplicated:** If `permitnumber` appears more than once with `status = 'Issued'`, that's a grain integrity failure — not a data quality footnote.

**Two distinct failure modes clarified:**
- **FM1 — Grain integrity failure:** Duplicate rows violating the PK guarantee (e.g., duplicate `permitnumber` in `fct_permits`). Root cause: bad deduplication in staging.
- **FM2 — Mixed-grain facts:** Two different fact types (snapshot vs. change) coexisting in the same table (e.g., adding `pct_change_from_prior_year` to a snapshot table). These span different business questions and create NULL-filled rows at the earliest vintage.

**"Facilitate the calculation, don't pre-answer it"** — The key data engineer vs. analyst mindset shift. Engineers build tables that make calculations possible; they don't pre-compute the answer and store it. FM2 is what happens when you forget this.

**G6 emerged from the discussion:** the learner described wanting district-level histogram visualizations for ACS attributes. Working through the transformation process (tract → bridge → district → bin), it became clear that adding bins to `fct_tract_acs` would change its grain (5 identical rows per tract per period). Two separate tables were the right call: G4 stays atomic, G6 is the pre-aggregated histogram.

## Grain statements defined

| Table | Grain |
|-------|-------|
| G1 `fct_permits` | One issued permit event (`status = 'Issued'`) |
| G2 `fct_district_year_zoning_composition` | District × vintage year × zoning code snapshot |
| G3 `bridge_tract_district_overlap` | Tract × district × boundary version overlap, where overlap exists |
| G4 `fct_tract_acs` | Census tract × ACS 5-year period (wide) |
| G5 `dim_date` | One calendar date |
| G6 `agg_district_acs_attributes_hist` | District × boundary version × census attribute × bin range |
